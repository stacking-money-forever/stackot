S46 — SQLite 일관 backup (owner launch contract, wave 03)

Task: ONE changeset. outbox SQLite의 **일관된** 스냅샷을 만들고, 그 스냅샷이 단독으로 유효함을 검증한다.

Base: 이 worktree의 HEAD. Owner가 launch 시 정확한 SHA를 기록한다.
Owner: 현재 Codex/Astra 스레드. 너는 후보(candidate)만 만든다. 커밋·푸시·머지·배포·릴리스 금지.

## 왜 (오너가 소스로 확인한 사실)
- 현재 백업 수단이 없다. WAL 모드이므로 파일을 그냥 복사하면 커밋된 최근 행이 `-wal`에 남아 사라질 수 있다(원장 failure trigger: "WAL 누락").
- 복구 drill(S47)과 rollback(S48)이 이 산출물에 의존한다.

## 편집 허용 범위 (그 외 파일 수정 금지)
- receiver/src/backup.ts (신규)
- receiver/test/backup.test.ts (신규)

금지: outbox.ts, server.ts, delivery.ts, router.ts, mapping.ts, normalize.ts, config.ts, gateway.ts, ingress.ts, redact.ts, telemetry.ts, metrics.ts, replay.ts, package.json, 기존 테스트 파일 수정.

## 요구 동작
1. `backup.ts`에 일관 스냅샷 함수를 만든다(예: `export async function backupOutbox(sourcePath: string, destPath: string): Promise<{ bytes: number }>`).
   - SQLite의 일관 스냅샷 기능을 사용한다(예: `VACUUM INTO`). 파일 복사(`copyFile`)는 금지한다 — WAL 내용을 놓친다.
   - 경로는 안전하게 이스케이프한다(SQL 문자열에 직접 삽입되는 경우 단일 인용부호 이스케이프 필수).
   - 원본이 없거나 열 수 없으면 명확히 실패한다. 실패 시 목적지에 반쪽 파일을 남기지 않는다.
   - 목적지가 이미 존재할 때의 동작을 정하고 receipt에 문서화한다(기존 백업을 조용히 덮어쓰지 말 것).
2. CLI 진입점을 제공한다(같은 파일에서 `import.meta.main`): `bun src/backup.ts <dest-path>`, 원본은 `STACKOT_OUTBOX_PATH`(기본값은 `server.ts`와 동일 규칙). 종료 코드: 성공 0, 실패 1, 인자 누락 2. 출력은 사람이 읽을 한 줄 + `bytes`.
3. 스냅샷은 **단독 파일**이어야 한다: 복사본만 열어도 데이터가 온전해야 하며 `-wal`/`-shm`에 의존하지 않는다.
4. 원본 outbox의 내용·스키마·PRAGMA·기존 동작을 바꾸지 않는다(읽기만 한다).

## 테스트 요구 (receiver/test/backup.test.ts)
- **WAL 포함(핵심)**: outbox를 만들고 행을 넣은 뒤 **체크포인트하지 않고**(행이 `-wal`에만 있음) 백업한다. 스냅샷을 열어 (a) `PRAGMA integrity_check`가 `ok`, (b) `-wal`에만 있던 행이 스냅샷에 존재, (c) 총 행 수가 원본과 일치함을 단언한다.
- 단독성: 스냅샷 파일을 다른 디렉터리로 복사하고 원본 디렉터리를 삭제한 뒤 복사본을 열어 데이터가 온전함을 단언한다.
- 상태 보존: pending/dead_letter/delivered 행의 state·attempts·last_error·event JSON이 스냅샷에서 동일하다.
- 실패 경로: 원본이 없으면 실패하고 목적지가 생성되지 않는다(또는 명확한 오류).
- CLI: 정상 실행 시 종료 코드 0과 출력, 인자 누락 시 2, 원본 없음 시 1.
- 실제 네트워크를 쓰지 않는다.
