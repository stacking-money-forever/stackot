## 현재 결함 (오너가 소스로 확인함)
- delivery.ts의 DeliveryDrainer는 실패 시 outbox.retry만 호출한다. DeliveryOutbox 포트에 fail이 아예 없다.
- outbox.ts의 fail()은 dead_letter와 last_error를 기록하는 유일한 함수지만 호출자가 없다. 그래서 MAX_DELIVERY_ATTEMPTS(5)와 last_error 컬럼이 죽은 코드이고, 영구 실패 job이 60초 간격으로 무한 재시도된다.

## 요구 동작
1. DeliveryOutbox 포트에 `fail(id: string, attempts: number, error: string): void`를 추가한다.
2. DeliveryDrainer.drain()의 실패 경로에서 `this.outbox.fail(job.id, job.attempts + 1, message)`를 호출한다. message는 throw된 Error의 message, 또는 forward 결과가 `{ ok: false }`일 때 상태코드를 포함한 문장(예: `gateway rejected delivery (status 502)`)이다. DeliveryForwarder 반환 타입은 `{ ok: boolean; status?: number }`로 최소 확장해도 된다.
3. Outbox.fail의 현재 의미를 유지한다: attempts >= MAX_DELIVERY_ATTEMPTS면 state='dead_letter' + last_error 저장, 미만이면 retry.
4. dead_letter 행은 due()가 계속 반환하지 않아야 한다.
