S43 — queue/dead-letter 메트릭 (owner launch contract, wave 03)

Task: ONE changeset. outbox의 적체 상태(pending 수, 가장 오래된 pending 나이, dead-letter 수)를 조회 가능한 메트릭으로 노출한다.

Base: 이 worktree의 HEAD. Owner가 launch 시 정확한 SHA를 기록한다.
Owner: 현재 Codex/Astra 스레드. 너는 후보(candidate)만 만든다. 커밋·푸시·머지·배포·릴리스 금지.

## 왜 (오너가 소스로 확인한 사실)
- 현재 outbox 적체를 알 방법이 없다. `due()`는 한 건, `has()`는 boolean뿐이고, 운영자는 sqlite 파일을 직접 열어야 한다.
- S41로 `/status`가 생겼지만 Gateway/준비 상태만 담는다. 적체(가장 오래된 pending의 나이, dead-letter 수)는 어디에도 없다 → 무음 적체가 가능하다.

## 요구 동작
1. `Outbox.stats()`:
   - 반환: `{ pending: number; deadLetter: number; delivered: number; oldestPendingAgeMs: number | null }`
   - 집계는 SQL 한 번으로 계산한다(행을 JS로 끌어와 세지 않는다). `oldestPendingAgeMs`는 pending이 없으면 null.
   - 스키마·컬럼·PRAGMA·기존 메서드 동작을 바꾸지 않는다.
2. `metrics.ts`:
   - `export type QueueMetrics = { pending: number; deadLetter: number; delivered: number; oldestPendingAgeMs: number | null }`
   - `export function collectMetrics(stats: OutboxStats): QueueMetrics` (형태 정규화; 음수/NaN은 0 또는 null로 안전화)
   - `export function toLogLine(metrics: QueueMetrics): string` — 한 줄 JSON, `ts` 포함(예: `{"ts":..., "event":"queue.metrics", ...}`), secret이 들어갈 여지가 없어야 한다.
   - `export const METRICS_INTERVAL_MS = 60_000` 같은 주기 상수를 export한다.
3. `server.ts`:
   - 위 주기로 `console.log(toLogLine(collectMetrics(outbox.stats())))`를 남긴다(타이머는 종료 시 해제).
   - `GET /status`가 queue 통계를 포함한다(`health.ts`의 statusReport 확장 사용).
   - 메트릭 조회 실패가 프로세스를 죽이지 않게 한다(오류는 redaction 후 로그).
4. 기존 회귀 금지: `/healthz`=`ok`, `/readyz`=`ready`/503, S09A/S09B/S21b/S39/S41 계약, outbox의 기존 동작.

## 테스트 요구 (receiver/test/metrics.test.ts)
- 알려진 행 구성 테스트(핵심): pending 2건(그중 하나는 `received_at`을 과거로 조작해 나이를 알 수 있게), dead_letter 1건, delivered 3건을 만들고 `outbox.stats()`가 정확히 그 수를 보고하는지 단언한다. `oldestPendingAgeMs`가 조작한 나이와 근사(허용 오차 내)인지 단언한다.
- pending이 없으면 `oldestPendingAgeMs`가 null이다.
- 상태별로 행이 없을 때 0을 보고한다(누락 없음).
- `toLogLine`이 파싱 가능한 JSON이고 필수 필드가 모두 있다.
- `collectMetrics`가 비정상 입력(음수, NaN)을 안전하게 처리한다(0 또는 null).
- 프로세스 레벨: 서버가 실제로 `queue.metrics` 라인을 남기고 `/status`가 통계를 담는지 확인한다(가능하면 `METRICS_INTERVAL_MS`를 줄일 수 있는 방법을 쓰거나, 시작 직후 1회 emit하도록 설계한다 — 방법과 근거를 receipt에 기록).
